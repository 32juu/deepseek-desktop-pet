# 产品需求文档（PRD）：DeepSeek 桌面学习助手

> 版本 v1.0 ｜ 状态：待评审 ｜ 对应阶段：Phase 0 设计阶段产出物
> 范围：本文档定义**做什么、不做什么、怎么验收**。不定义实现细节。
> 上游依据：`CLAUDE.md`（硬约束）、`docs/roadmap.md`（阶段划分）、`docs/character-spec.md`（视觉状态机）、`docs/ai-levels.md`（AI 能力分级）。
> 本文档与上述文档冲突时，以 `CLAUDE.md` 为准，并把偏差登记到 `docs/dev-log.md`。

## 1. 产品定位

### 1.1 一句话价值主张

> **把"我今天学了什么"变成"AI 知道我哪里弱、下一步该学什么"——一个会记住你学习过程的桌面学习助手。**

### 1.2 定位展开

| 维度 | 定位 |
|---|---|
| 产品品类 | 桌面 AI 学习助手 / Personal Learning OS（轻量级） |
| 交互入口 | 常驻桌面的"蓝色大肥鱼娘"形象 + 对话窗口 + 学习面板 |
| 核心资产 | 用户长期学习数据（行为 → 知识 → 画像） |
| 差异点 | 不是"回答问题的 AI"，而是"理解你学习状态的 AI" |
| 使用形态 | 单用户、本地运行、常驻后台、低打扰 |

### 1.3 明确不是什么

| 它**不是** | 说明 |
|---|---|
| ❌ 桌宠（以逗趣/陪伴为卖点） | 桌宠只是交互外壳。判断标准：若移除全部学习功能，产品即失去存在意义。 |
| ❌ 聊天客户端（套壳 ChatGPT） | 聊天只是 MVP 的必要通路，不是终点。对话必须能读到真实学习数据。 |
| ❌ 通用效率工具 / TODO 应用 | 一切功能必须服务于"学习数据沉淀 → AI 理解 → 个性化学习"闭环，否则不做。 |
| ❌ 知识付费/内容平台 | 不自建题库内容生态，题目与知识来自用户自己的学习行为。 |
| ❌ 多人在线/社交产品 | MVP 无用户系统、无云同步、无分享。 |

### 1.4 成功的样子（三年视角）

用户连续使用 3 个月后，系统能基于真实数据说出：
"你在 MySQL 索引方向最近 14 天错了 9 题，Redis 缓存三兄弟已稳定掌握"——且这句话的每一条依据都可追溯。

### 1.5 关键术语（统一口径，供 `architecture.md` / `database.md` / `plugin-spec.md` 复用）

| 术语 | 定义 |
|---|---|
| 学习会话（study_session） | 一段有明确起止的专注学习过程，是行为数据的最小单位，由番茄钟插件产生 |
| 学习目标（goal） | 用户设定的阶段性目标（如"两周搞定 Redis"），可选，可关联多个学习会话 |
| 科目（subject） | 学习内容的分类维度（如 Redis、MySQL、英语），是统计分组的主轴 |
| 知识点（knowledge_point） | 从学习行为中沉淀出的可掌握单元（Phase 5 引入） |
| 学习记录 | 学习会话 + 相关行为（对话、错题、笔记）的统称 |
| AI 学习报告（ai_report） | 由统计接口数据 + LLM 生成的文本结论，必须携带数据依据元信息 |
| 桌宠状态 | `docs/character-spec.md` 定义的视觉状态，由事件驱动，不承载业务语义 |
| 插件 | 可被用户使用、可产生学习数据、可被 AI 调用的能力模块 |
| 统计接口 | 只读聚合接口，返回可核对的事实数据；**不经 LLM**，LLM 只在其上做表达 |

### 1.6 AI 使用边界（产品层声明）

本产品**不为了 AI 而 AI**。判断某功能是否该用 LLM 的唯一标准：

| 场景 | 归属 | 理由 |
|---|---|---|
| 时长统计、科目分组、趋势计算、目标进度 | 普通 Java 逻辑 | 精确计算，LLM 会算错 |
| 提醒触发条件（如"3 天未学习"） | 普通 Java 逻辑 | 规则明确、需可预测可测试 |
| 对话问答、解释概念 | LLM | 语言理解与生成 |
| 学习总结、薄弱点描述、下一步建议 | LLM（输入必须是真实统计数据） | 归纳与表达 |
| 数据一致性、权限判断、事务边界 | 普通 Java 逻辑 | 正确性与安全不可交给概率模型 |

**红线**：任何 AI 输出的学习结论，都必须能回答"用了哪些数据"。做不到就不上线。

## 2. 目标用户与使用场景

### 2.1 目标用户画像

| 画像 | 特征 | 核心痛点 | 对产品的期待 |
|---|---|---|---|
| **A. 面试冲刺的 Java 后端学习者**（首要） | 在职/待业，每天 1~3 小时刷八股与算法，周期 1~3 个月 | 学过的忘得快；错题散落在各处；不知道薄弱点在哪 | 记录每段时间学了什么、错在哪，考前能给出针对性复习清单 |
| **B. 考研 / 考证人群** | 长期（3~12 个月）固定科目，需要稳定节奏 | 难以坚持；学习时长无感知；进度不透明 | 番茄钟 + 时长统计 + 连续性反馈，把"坚持"量化 |
| **C. 在校学生（课程 / 自学）** | 多科目并行，碎片时间 | 笔记与知识不成体系 | 科目维度记录 + AI 阶段性总结 |
| **D. 终身学习者 / 技术爱好者** | 学习内容发散，无固定目标 | 学了就过，没有沉淀 | 低打扰记录 + 按需回顾 |

**首个验证对象是画像 A**：他的学习行为最密集、错题最可量化、对"薄弱点分析"付费意愿最强。

### 2.2 典型场景（动作 → 响应 → 沉淀数据）

> 所有场景以现状（MVP 完成后）为准；标注【MVP】的为本次必须跑通，标注【后续】的对应 `docs/roadmap.md` 更高阶段。

**场景 1：开始一段专注学习【MVP】**

| 环节 | 内容 |
|---|---|
| 用户动作 | 双击桌宠 → 打开学习面板 → 选科目"Redis"、目标 25 分钟 → 点开始 |
| 系统响应 | 桌宠切 `learning`（见 `docs/character-spec.md`），显示计时气泡；倒计时结束弹温和提醒 |
| 沉淀数据 | `study_session`：开始/结束时间、实际时长、科目、关联目标、完成状态；发出 `STUDY_SESSION_STARTED` / `STUDY_SESSION_FINISHED` 事件 |

**场景 2：学习中遇到问题直接问 AI【MVP】**

| 环节 | 内容 |
|---|---|
| 用户动作 | 学习面板里输入"Redis 缓存穿透和击穿的区别" |
| 系统响应 | 桌宠 `loading` → `talking`，流式输出答案；桌宠气泡显示"正在答疑" |
| 沉淀数据 | 会话与消息持久化；该对话**关联当前学习会话**（后续可回溯"这段学习里我问了什么"） |

**场景 3：一天结束，让 AI 总结今天【MVP】**

| 环节 | 内容 |
|---|---|
| 用户动作 | 点"生成今日总结"（或直接问"我今天学得怎么样？"） |
| 系统响应 | 后端读取今日真实记录 → 交给 LLM 生成结论文本 → 展示，并附"依据：X 条记录 / 时间范围" |
| 沉淀数据 | `ai_report`：类型、时间范围、输入数据摘要（记录条数/ID 列表）、生成文本、模型、token 消耗 |
| 关键约束 | 当日无记录时**必须**回答"今天还没有学习记录"，禁止编造 |

**场景 4：考前看薄弱点【Phase 5 后】**

| 环节 | 内容 |
|---|---|
| 用户动作 | 问"我 Redis 学得怎么样？" |
| 系统响应 | Agent 调用错题/知识点统计工具 → 输出掌握度分布与建议复习清单 |
| 沉淀数据 | 知识点掌握度快照；Agent 调用轨迹（工具名、参数、结果摘要） |

**场景 5：长时间没学习，被温和拉回【Phase 8 后】**

| 环节 | 内容 |
|---|---|
| 用户动作 | 连续 3 天未开始任何学习会话 |
| 系统响应 | 桌宠切 `concern`，气泡"要不要来 25 分钟？"，**每天最多 1 次**，可在设置关闭 |
| 沉淀数据 | 提醒发送记录（时间、类型、是否被点击），用于后续调优频率 |

**场景 6：拖着桌宠换个位置（无学习语义的交互）**

| 环节 | 内容 |
|---|---|
| 用户动作 | 拖拽桌宠 |
| 系统响应 | 窗口跟随，位置持久化，重启后回到原位 |
| 沉淀数据 | 窗口位置与缩放配置 |

## 3. 范围定义

### 3.1 MVP 范围（In Scope）

MVP 的目标**只有一个**：跑通 `CLAUDE.md` 第 7 节的闭环。为此纳入以下能力：

| 模块 | 纳入内容 |
|---|---|
| 桌宠客户端（Tauri） | 无边框透明常驻窗口、拖拽、位置持久化、置顶、显示/隐藏、系统托盘、右键菜单、基础设置页 |
| 角色状态机 | 8 个 MVP 状态：`idle` `blink` `sleep` `talking` `loading` `learning` `success` `concern`（定义见 `docs/character-spec.md`） |
| AI 对话 | LLM API 配置、单模型默认 + 可切换、流式输出、会话列表与消息持久化、基础上下文（最近 N 轮）、token 统计 |
| 学习系统 | 学习目标（可选）、学习会话记录、学习时长统计、7 日趋势 |
| 第一个插件 | 番茄钟 / 学习计时插件（严格走插件规范，见 `docs/roadmap.md` Phase 4，MVP 先按最小插件协议落地） |
| 数据持久化 | MySQL 8 落库；后端提供统计接口 |
| AI 学习总结 | "今日总结"一键生成，附带数据依据元信息 |
| 设置 | API Key（安全存储）、模型选择、科目管理、提醒开关、数据导出 |

### 3.2 明确不做（Out of Scope）

**A. 与 CLAUDE.md 约束一致（因为"没有真实需求就已产生"）**

| 不做 | 为什么现在不做 |
|---|---|
| 微服务拆分 | 单用户单机，拆服务只增加部署与调试成本（CLAUDE.md 约束 4） |
| MQ / 消息队列 | MVP 的事件量级用进程内事件总线足够 |
| 分布式 / 多 Agent、复杂工作流 | 闭环未验证前构建 Agent 是本末倒置（CLAUDE.md 约束 10、第 7 节） |
| 插件市场 / 在线安装 / 插件沙箱 | Phase 9 才探索；MVP 插件与主程序同仓编译 |
| 复杂权限系统 | MVP 只有 1 个受信插件，权限模型只需在元数据里预留字段 |
| RAG / 向量数据库 | Phase 7；当前无知识文档语料，embedding 无对象 |
| 多用户 / 账号体系 / 云同步 | MVP 为单用户本地；保留 `user_id` 字段但不实现登录（见 §9 风险 R4） |

**B. 产品主动砍掉（因为不服务于核心闭环）**

| 不做 | 为什么现在不做 |
|---|---|
| 桌宠皮肤商店 / 换装 | 无关学习闭环；且增加美术与资源管理成本 |
| TTS 语音朗读、语音对话 | 增加延迟与成本，对"数据沉淀"零贡献 |
| 社交、排行榜、打卡分享 | 单人产品，无社交场景；打卡已由时长统计隐式覆盖 |
| 游戏化复杂成就系统 | 先验证"看数据"本身是否有用，再考虑激励层 |
| Live2D 动态立绘 | MVP 用序列帧即可表达 8 个状态；是否上 Live2D 见 §9 风险 R3 |
| 自建题库内容 / 内置教材 | 内容运营不是本产品能力；题库插件面向"用户自己的题" |
| 移动端 / Web 端 | 定位是桌面常驻，跨端只增加验证成本 |
| 在线升级（自动更新） | 单机自用阶段手动替换即可，Phase 9 后再考虑 |
| 多语言 i18n | 目标用户为中文学习者，先不引入 i18n 框架开销 |

## 4. 用户故事与验收标准

### 4.1 角色：学习者（learner）

| ID | 用户故事 | 验收标准（AC） |
|---|---|---|
| US-01 | 作为学习者，我希望启动后桌宠出现在桌面上，不打断我当前工作 | ① 冷启动到可见 ≤ 3s；② 窗口无边框、透明背景、无任务栏按钮；③ 出现在上次位置（首次为右下角）；④ 默认置顶且不抢焦点；⑤ 可在设置中关闭置顶 |
| US-02 | 作为学习者，我希望桌宠"活着"，而不是一张静态图 | ① 静止 10s 内至少触发一次 `blink`；② `idle` 持续微浮动；③ 无操作 10min 进入 `sleep`；④ 鼠标悬停/点击可唤醒到 `idle`；⑤ 所有状态切换无白屏、无闪帧 |
| US-03 | 作为学习者，我希望随手拖动桌宠并记住位置 | ① 拖动跟手无卡顿；② 松手后 1s 内持久化；③ 重启后位置误差为 0；④ 拖到屏幕外时自动回收到可见区域 |
| US-04 | 作为学习者，我希望右键就能操作，不用翻菜单 | ① 右键菜单含"对话 / 开始学习 / 今日统计 / 隐藏 / 设置 / 退出"；② 每项 2 次点击内可达；③ 隐藏后可通过托盘图标恢复 |
| US-05 | 作为学习者，我希望配置自己的 LLM API Key | ① 支持 Base URL + API Key + 模型名三项配置；② 提供"测试连接"按钮并给出明确成功/失败原因；③ Key 不以明文出现在任何数据库表、日志、导出文件、前端持久化存储中；④ 配置界面可一键清除 Key |
| US-06 | 作为学习者，我希望和 AI 对话时能立刻看到回复在生成 | ① 首 token ≤ 2s（P95）；② 流式逐字显示；③ 生成期间桌宠为 `loading`，出错时切回并给出可读错误；④ 支持中断生成；⑤ 网络失败可重试且不产生重复消息记录 |
| US-07 | 作为学习者，我希望对话记录不会丢 | ① 关闭应用重开后会话与消息完整；② 会话列表按最近活跃排序；③ 支持重命名与删除；④ 消息落库与界面展示一致（条数、顺序、角色） |
| US-08 | 作为学习者，我希望一键开始一段专注学习 | ① 选科目 + 时长即可开始；② 期间桌宠为 `learning` 且气泡显示剩余时间（可从 `docs/character-spec.md` 状态机取）；③ 计时期间重启应用，会话不丢失且按实际时间结算；④ 计时结束有温和提醒（非全屏弹窗） |
| US-09 | 作为学习者，我希望被打断时能正确处理这段学习 | ① 提供"提前结束"；② 记录实际时长与结束原因（完成/放弃）；③ 放弃的会话是否计入统计有明确规则（默认：计入时长但不计入"完成次数"） |
| US-10 | 作为学习者，我希望看到今天/最近 7 天学了多久 | ① 统计页展示今日总时长、会话数、科目分布、7 日趋势；② 数字与数据库直查结果**逐条一致**；③ 无数据时展示空状态而非 0 值误导 |
| US-11 | 作为学习者，我希望让 AI 总结我的学习情况 | ① 一键"生成今日总结"与自然语言提问两种入口；② 总结内容必须基于真实记录，界面显示依据（时间范围、记录条数）；③ 无记录时明确说明无数据，禁止编造；④ 报告入库，可回看历史报告 |
| US-12 | 作为学习者，我希望管理自己的学习科目 | ① 可增删改科目（名称、颜色）；② 已被会话引用的科目不可硬删除（软删除或阻止，并有提示）；③ 科目用于统计分组 |
| US-13 | 作为学习者，我希望数据在我自己手里 | ① 提供"导出全部学习数据"（JSON/CSV）；② 提供数据库文件位置指引；③ 导出内容不含 API Key；④ 删除数据需二次确认且说明影响范围 |
| US-14 | 作为学习者，我希望学习时不被频繁打扰 | ① MVP 中主动提醒仅 `concern` 一种，默认**关闭**或每天最多 1 次；② 所有提醒可单独关闭；③ 不出现强制全屏、无关闭按钮的窗口 |

### 4.2 角色：开发者 / 维护者（本项目自用，非交付角色）

| ID | 用户故事 | 验收标准（AC） |
|---|---|---|
| US-D1 | 作为维护者，我希望模块边界清晰，改一处不牵连全项目 | ① 目录结构符合 `docs/architecture.md`（待产出）模块划分；② 插件代码不 import 桌面 UI 或直接访问 DB；③ 单模块可独立编译/测试 |
| US-D2 | 作为维护者，我希望新插件能通过事件接入而不改旧代码 | ① 番茄钟结束仅发布事件；② 统计模块以订阅者身份消费；③ 新增一个订阅者无需修改番茄钟代码 |
| US-D3 | 作为维护者，我希望 AI 结论可追溯以便调试 | ① 每次 AI 学习分析落库：模型、prompt 版本、输入记录 ID 集合、输出；② 可据记录复现该次分析的数据范围 |

## 5. 功能清单与优先级

优先级口径：**P0 = MVP 必须，缺一则闭环不成立**；**P1 = MVP 之后立即做，显著提升体验**；**P2 = 有真实需求再做**。

| ID | 功能 | 优先级 | 所属 Phase（见 `docs/roadmap.md`） | 验收要点 |
|---|---|---|---|---|
| F-01 | 桌宠常驻窗口（透明/无边框/置顶/托盘） | P0 | Phase 1 | US-01、US-04 |
| F-02 | 拖拽与位置持久化 | P0 | Phase 1 | US-03 |

## 6. 核心闭环端到端用户旅程

> 主线：`启动桌宠 → AI 聊天 → 开始学习 → 番茄钟 → 学习记录入库 → 统计 → AI 生成学习总结`
> 状态命名与优先级见 `docs/character-spec.md`。下表"界面表现"是可验收的界面断言。

| 步骤 | 用户动作 | 界面表现（可验收） | 系统行为 | 落库数据 |
|---|---|---|---|---|
| 1 | 双击桌面图标启动 | 3s 内桌宠出现在上次位置；`idle`，尾巴摆动，偶发 `blink`；无任务栏按钮 | Tauri 读配置 → 拉起/连接本地后端 → 健康检查通过 | 启动日志（时间、版本） |
| 2 | 双击桌宠（或右键→对话） | 对话窗口从桌宠旁展开；桌宠切 `talking` | 拉取最近会话；无则新建 | `conversation`（标题、创建时间） |
| 3 | 输入"Redis 缓存击穿怎么解决？" | 发送后立刻上屏用户气泡；桌宠切 `loading`；AI 气泡逐字出现；完成后回 `talking`/`idle` | 组装上下文（系统提示 + 最近 N 轮）→ 调 LLM 流式接口 → 落库 | `message`（user/assistant 两条）；`llm_call`（模型、token、耗时） |
| 4 | 点"开始学习" | 进入计时面板：科目下拉、25/45/60 分钟预设、开始按钮；桌宠切 `learning` | 创建学习会话（进行中），发布 `STUDY_SESSION_STARTED` | `study_session`（开始时间、科目、预计时长、状态=进行中） |
| 5 | 番茄钟计时中（25min） | 桌宠保持 `learning`，气泡显示剩余时间与科目；计时以浮层呈现，不打断其他应用 | 计时在前端推进 + 后端对账（防止窗口刷新/休眠导致漂移）；若期间 AI 有响应则临时 `loading` 后回 `learning` | 无（如需则写心跳/检查点） |
| 6 | 计时结束 | 桌宠切 `success`（连续多轮可升级 `celebration`，P1）；温和提示"休息 5 分钟"；统计数字**即时更新** | 结算会话：实际时长、完成状态；发布 `STUDY_SESSION_FINISHED` | 更新 `study_session`（结束时间、实际时长、状态=完成）；`event_log` |
| 7 | 打开"今日统计" | 今日总时长、会话数、科目分布、7 日趋势图；数值与 DB 直查一致 | 统计服务聚合查询（走 Repository，不经过 LLM） | 无写入（读路径） |
| 8 | 点"生成今日总结" | 桌宠 `loading` → 展示结论文本；附"依据：今日 3 条记录 / 09:12–11:40"；生成中可取消 | 取当日统计 + 会话明细 → 组 prompt → 调 LLM → 落库 | `ai_report`（类型、范围、输入记录 ID 集、文本、模型、token） |
| 9 | 追问"那我明天该学什么？" | 回复基于第 8 步数据与近期记录；**无数据时明确说明不知道** | 复用统计接口 + 最近 N 天数据；若上下文不足则显式声明数据不足 | `message`；可选 `ai_report` |

**闭环验收判定（Phase 0 门槛）**：一次连续操作中完成步骤 1→8，且步骤 7 的数字与步骤 6 落库结果一致、步骤 8 的报告能指出其数据来源，即视为闭环跑通。

## 7. 非功能需求

| 类别 | 指标 | 目标值 | 验证方式 |
|---|---|---|---|
| 启动性能 | 冷启动到桌宠可见 | ≤ 3s（P95） | 重复 10 次计时 |
| 启动性能 | 常规启动（后端/DB 已在运行） | ≤ 2s | 同上 |
| 运行资源 | 桌宠客户端常驻内存 | ≤ 150MB（空闲态） | 任务管理器连续观察 30min |
| 运行资源 | 空闲 CPU 占用 | 平均 ≤ 2%（动画播放中 ≤ 5%） | 同上 |
| 交互性能 | 对话首 token 延迟 | ≤ 2s（P95，网络正常） | 20 次调用统计 |
| 交互性能 | 统计页加载 | ≤ 500ms（1 万条会话内） | 造数据压测 |
| 数据规模 | 单用户 3 年学习会话量 | 支持 ≥ 5 万条 `study_session` 不降级 | 造数据验证 |
| 离线可用性 | 断网时 | 桌宠、番茄钟、统计、历史查看**全部可用**；AI 对话/总结明确提示"需要网络"且不产生脏数据 | 断网演练 |
| 数据安全 | API Key | 存于系统凭据管理器（Windows Credential Manager / 等），不落库、不进日志、不进导出 | 全仓库 + DB + 日志检索 Key 片段 |
| 数据安全 | 数据库 | 本机 MySQL 8；提供每日自动导出（保留最近 7 份）到本地目录 | 检查导出文件生成与轮转 |
| 数据安全 | 崩溃恢复 | 进行中的学习会话在异常退出后按实际时间结算，不产生零时长/负数记录 | 强杀进程演练 |
| 隐私 | 数据流向 | 学习数据仅存本地；仅"用户主动发起的对话/总结"内容发送给所配置的 LLM 服务商 | 抓包确认 |
| 隐私 | 透明度 | 设置页明确列出"哪些数据会发给模型服务商" | 界面走查 |
| 可用性 | 少打扰 | MVP 默认不主动弹窗；唯一提醒类型默认每天 ≤ 1 次且可关闭 | 界面走查 + US-14 |
| 可维护性 | 日志 | 后端结构化日志，含请求 ID；错误日志含可操作上下文；敏感字段脱敏 | 代码走查 |
| 兼容性 | 平台 | MVP 优先 Windows 10/11 x64；macOS 列为后续验证 | 目标机运行 |

## 9. 风险与未决问题

### 9.1 风险清单

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | LLM API 成本失控 | 长期使用费用上升、可能放弃使用 | 默认选用低价模型；设置页显示本月 token 与估算费用；提供"仅本地统计、不调用 AI"模式；总结类请求限制输入长度 |
| R2 | LLM 幻觉污染学习判断 | 用户被错误结论误导，摧毁信任 | 所有 AI 学习结论附数据依据（记录条数/时间范围）；无数据必须说无数据；关键结论保留原始数据入口可核对（M9 强制校验） |
| R3 | Live2D 与否未决 | 影响美术工作量与状态机实现方式 | MVP 用序列帧表达 8 状态，接口层抽象"表情/状态播放器"，未来可替换为 Live2D 而不改业务层 |
| R4 | 是否引入用户系统 | 影响数据模型与鉴权 | MVP 不实现登录，`user_id` 字段预留但不启用；若未来服务化再迁移（登记到 `docs/dev-log.md`） |
| R5 | 单机 Tauri + Java + MySQL 三进程部署复杂 | 用户安装门槛高，违反"轻量"预期 | 由 Tauri 侧负责后端进程生命周期（启动/健康检查/退出清理）；文档提供一键启动脚本；评估后续将后端打包为 sidecar |
| R6 | 首次使用需装 MySQL | 上手成本高，可能劝退 | 提供初始化脚本 + 建库 SQL；若成本不可接受，可评估嵌入式方案但仍保持仓储层抽象（见 R7） |
| R7 | MySQL 与桌面单机形态不完全匹配 | 迁移成本、体积 | 仓储层（Repository）与具体数据库解耦；技术前提已定 MySQL 8（用户要求数据可直连查看），不做双实现 |
| R8 | 美术资源（13 状态 + 8 表情）工作量大 | 状态机无法完整交付 | MVP 只做 8 状态（F-03），其余列为 P1（F-21）；资源以 `docs/character-spec.md` 为唯一验收依据 |
| R9 | 状态机与业务耦合 | 后续加功能时状态混乱 | 状态切换由事件驱动（`STUDY_SESSION_*`、LLM 请求开始/结束），UI 只订阅状态，业务代码不直接改动画 |
| R10 | 学习数据隐私顾虑 | 用户不愿开 AI 功能 | API Key 与数据本地存储、可导出、可删除；明确告知发送范围（§7 隐私） |
| R11 | MVP 范围再次膨胀 | 闭环迟迟跑不通 | 以 §3.2 清单为硬边界；新增需求必须回答"是否服务于数据沉淀 → AI 理解"（`CLAUDE.md` 第 7 节自检） |
